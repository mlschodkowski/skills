# Simple Language

Use this skill for the requested text or explanation. It is not a global tone rule.

1. Identify the reader and the action they must take. Ask one question only if the missing context changes the meaning.
2. Extract the facts, decision, commands, risks, and next action.
3. Prefer ASD-STE100 or similar plain-language principles and aim for approximately CEFR B2 language when the reader and subject permit. Treat both as guidance, not hard requirements.
4. Rewrite with short active sentences, concrete verbs, one term per concept, and explicit conditions and results.
5. Remove filler, status theatre, vague claims, repeated context, and unnecessary headings.
6. Preserve exact identifiers, commands, paths, API names, error text, quoted text, and legal text.
7. Preserve the author's natural voice. Adapt the language to the reader, domain, and purpose instead of applying a fixed output template.

Return only the requested artifact unless the user asks for an explanation. Use `$simple-language` for explicit invocation.

Do not use this skill to change code logic or to flatten a creative or personal voice.
